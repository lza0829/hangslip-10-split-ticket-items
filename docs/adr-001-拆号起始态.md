# ADR-001 拆号另立：拆出票起始态口径

状态：已采纳（全局唯一口径）
日期：2026-11-22
范围：仅覆盖「一票多件 → 拆号另立」的拆票起始态；并票吞并另立需求，不在本决策内。

## 背景

一票多件在车间中途需要拆号另立时，拆票回执、新票起始工序、原票残留件、对象键归属、
水位、工序轨页必须联动，且满足：

- 件数守恒：拆出件数之和严格等于原票减少的件数；
- 拆号同事务：任一联动点失败整体回滚，杜绝半截拆号（衣物件双挂）；
- 并发拆号不得负件数、不得双加在途水位。

存在两种候选架构，全局只能贯彻一种：

- 架构一「以拆出票独立起算为准」：新票从「已收」起算；原票减去对应衣物件，无残留则
  关为「已拆」；水位按新开与原关规则调整且可重放。
- 架构二「以继承原票现行态为准」：拆出票带上原票现行工序含义后独立推进；禁止拆后两票
  共用同一衣物件键。

## 决策

采用**架构二：继承原票现行态**。

1. 新票 `status` 初始值 = 拆号瞬间原票的 `status`，只允许在
   `已收/水洗/烘干/熨烫/待取` 五种在途可推进态上拆号；`已取/已拆/超期隔离/丢失隔离`
   一律拒绝。
2. 新票自带一条起始事件，`from_status = NULL`、`to_status = 原票现行态`，note 注明
   「拆号另立自〈原票号〉」，使工序轨页能解释「新票为何一出生就在水洗中」。
3. 衣物件键归属排他：拆出的衣物件从原票 `ticket_items` 按件数核减（清零行删除），同事务
   插入新票行；任一衣物件在拆后只可能挂在一张票上，禁止两票共用同一衣物件键。
4. 原票拆后仍有残留件 → 保持原态继续推进，事件记「拆号另立〈新票号〉，拆出 N 件」；
   原票拆后无残留 → 状态置为新终态 `已拆`、写 `closed_at`，事件记
   `from_status=原态, to_status='已拆'`。
5. 水位「在途票」在同事务末尾按全量重算（`refresh_in_flight`），不做增量加减：
   - 原票残留：票数 1 → 2（新票在途），水位 +1；
   - 原票关已拆：票数 1 → 1（原票出在途、新票入在途），水位净 0；
   全量重算天然可重放，杜绝双加。
6. 并发安全：拆号在单个 `BEGIN IMMEDIATE` 事务内完成，先核减校验（`qty >= 拆出数`，
   失败抛 409）再写入；SQLite 写锁串行化并发拆号，后到事务读到的是前事务提交后的件数，
   负件数在事务内即被拦截，不可能落库。
7. 拆票回执落独立表 `split_receipts`（原票、新票、拆出明细、件数、操作人、时间），
   原票与新票的事件流各留指针，互为凭证。

## 否决架构一的理由

- 工序事实错误：已在水洗/烘干中的物理衣物被拆到新票后回退为「已收」，必须重走全流程，
  与衣物实际所在工位矛盾；
- 轨页语义拧花：新票从已收起算而原票残件仍在水洗，正是「新票已待取、原票还在洗」类
  错乱的口径根源；
- 水位规则虽可重放，但「新开 +1 / 原关 -1」的增量口径在半截失败时需要补偿，
  不如同事务全量重算简单可靠。

## 不变量（测试必须守住）

1. 任意时刻 `SUM(ticket_items.qty)` 在拆号前后相等（件数守恒）；
2. 任一衣物件键（票号+衣物+备注）拆后唯一归属一张票；
3. 拆号后水位 = 状态不在 `已取/丢失隔离/已拆` 的票数（全量重算值）；
4. 并发两笔拆同一票，至多一笔成功超拆，成功笔数与件数核减一致，无负 qty 落库；
5. 新票起始态恒等于拆号时原票现行态。
